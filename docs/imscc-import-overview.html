IMSCC import — how it works

A feature-flagged reverse pipeline: upload a Canvas Common Cartridge, reconstruct a normal CAS course Editor, then optionally LLM-rebuild Blueprint, CDD, and Style so the course is editable end-to-end.

Gated by IMPORT_COURSES_ENABLED (default off)

End-to-end flow

1. Validate → 2. Start import → 3. Parse + rebuild Editor → 4. Reverse-gen design → 5. Open Editor
  1. Validate (sync, no DB) — extract ZIP + structural parse → title, counts, warnings.
  2. Start — create course shell (source_type="imscc"), CourseImport record, stage package to a temp path, enqueue job.
  3. Job — full parse → Editor rebuild → reverse-gen Blueprint / CDD / Style → finalize.
  4. UI — poll job status; on success navigate to /workspace/{courseId}/editor.

API surface

Mounted only when the feature flag is on — app/api/v1/routers/imports.py

Endpoint Role
GET /imports/health Capability probe
POST /imports/validate Pre-flight parse (no DB writes)
POST /projects/{id}/imports Start async import
GET /imports/{id} Import record / status
POST /imports/{id}/retry Re-run Blueprint / CDD / Style only
POST /imports/{id}/cancel Cancel active import job

Frontend wizard: /projects/:projectId/import (ImportWizardPage).

Parsing pipeline

Orchestrator: promptops_app/importers/imscc_importer.py — no database writes.

Step Module What it does
Extract package_extractor.py Safe unzip (size / ratio / entry caps); find imsmanifest.xml
Structure canvas_parser.parse_structure Modules + item stubs from manifest / module_meta.xml
Content canvas_parser.parse_course Bodies via HTML→MD and QTI quiz parsing
Model internal_model.py ICourse / modules / pages / assessments
validate_package = extract + structure. parse_package = extract + full content. Fatal zip/manifest problems raise PackageValidationError. Unsupported types (LTI, URLs, attachments, …) become warnings.

Background job stages

promptops_app/jobs/import_jobs.py → run_import_job

Progress Stage
10%Read staged package
30%parse_package
50–74%editor_builder.build → modules, generations, blocks + provenance
78%reverse_blueprint.build_blueprints
86%reverse_cdd.build_cdd
92%style_analyzer.build_style
96%Finalize (completed, provenance_ready=True)
Editor rebuild is required for success. Reverse-gen failures are non-fatal — the Editor stays usable. Retry re-runs design artifacts only via run_reverse_gen_job.

What gets persisted

  • CourseModule
  • Generation / Block
  • Lessons, quizzes, assignments, discussions

Design artifacts (LLM)

  • ModuleBlueprint
  • CourseDesignDocument
  • Style — pinned as course actives

After import

  • Behaves like a normal CAS course
  • Edit, regenerate, export all work
  • Re-export can use provenance for fidelity

Inverse of export

The importer is the intentional inverse of promptops_app/exporters/imscc_exporter.py. Product intent: legacy Canvas package → fully AI-editable CAS project (see PRD-CAS-Reverse-Pipeline.md / reverse_cas.md).
